# Расписание колледжа — версия с администрированием

## Запуск в Windows

Распакуйте архив в отдельную папку. Не заменяйте рабочую папку поверх без резервной копии.
Откройте терминал в папке `college_schedule`:

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python init_db.py
python setup_admin.py
python -m uvicorn web.app:app --reload
```

Если окружение уже есть, можно использовать его и установить зависимости.
`init_db.py` безопасен для повторного запуска: существующие записи не перезаписывает.
`setup_admin.py` задаёт логин и пароль. Пароль не выводится при вводе — это нормально.
Запустите его повторно, чтобы сменить пароль. Готового общего пароля в архиве нет.

Генератор: http://127.0.0.1:8000/
Админка: http://127.0.0.1:8000/admin

При входе браузер покажет стандартное окно логина и пароля (HTTP Basic).
Учётные данные могут оставаться в памяти браузера до закрытия сеанса.
Для доступа из интернета нужен HTTPS; локальный запуск привязан к 127.0.0.1.
Все изменения данных, включая старый PUT преподавателей, требуют входа.
Просмотр расписания и запуск генерации доступны без входа.

## Работа с данными

1. Преподаватели: ФИО, персональный годовой лимит, ставка, максимум пар, методические дни.
2. Группы: название, курс, специальность.
3. Предметы: название, специальность, справочные ID корпусов.
4. Учебная нагрузка: выберите группу, предмет и преподавателя из списков; укажите пары A/B.
5. Календарь: недели A/B, длительность пары, учётные часы за пару.
6. Нажмите «Проверить нагрузку», исправьте превышения и затем откройте генератор.

Поиск работает в каждом разделе. Записи можно добавлять, редактировать и удалять.
Удалить используемую группу, предмет или преподавателя нельзя, пока существуют назначения.
Частично заполненный учебный план разрешено сохранять: проверка/генерация сообщит о нехватке пар.
Изменение данных не пересчитывает уже показанное расписание: нажмите генерацию заново.

## Где хранятся данные

`college.db` — рабочая SQLite-база. Она содержит преподавателей и редактируемые наборы данных.
При первом запуске группы, предметы, нагрузка и календарь импортируются из `data/`.
После этого редактирование CSV не влияет на сайт. Даже пустой раздел не импортируется повторно.
Исходные CSV оставлены для истории и первичного развёртывания; старые автономные
`load_dataset()` / `view_schedule.py` предназначены для CSV и не являются источником сайта.
Сделать резервную копию: остановите сервер и скопируйте `college.db` в безопасное место.
Также сохраните `admin_credentials.json`, если хотите сохранить существующий вход.
Не публикуйте этот файл в Git. В нём хранится соль и PBKDF2-хеш, а не открытый пароль.

## Ограничения и часы

Годовые часы = пары A × недель A × коэффициент + пары B × недель B × коэффициент.
Проверка учитывает все назначения в базе, даже при генерации части групп.
Это часы указанного учебного плана, без неописанных внешних занятий и других обязанностей.
Ставка справочная: лимит задаётся полем «Годовой лимит часов», не вычисляется из ставки.
1080 — настраиваемое значение по умолчанию для нового преподавателя, не обязательный предел для всех.
Календарь из архива тестовый: коэффициент и недели нужно подтвердить в колледже.
80 минут и количество учётных часов за пару — разные параметры.

В расписании: 25 групп максимум в запросе, 5 дней, 4 слота, 3–4 пары у группы каждый день,
отсутствие пересечений, методические дни строго свободны, дневной максимум преподавателя.
Окна и одиночные пары преподавателей — мягкие штрафы. Гарантии нуля окон нет.
Методические дни выбираются администратором, генератор их сам не назначает.
Корпуса пока справочные: ограничения и переходы между корпусами алгоритм не проверяет.
Алгоритм MOVE/SWAP и его веса сохранены; скорость не была целью этой доработки.
Генерация ограничена 20 секундами, оптимизация — 65 итерациями / 500 попытками SWAP на итерацию.
Отображаемое время оптимизации не включает генерацию. Результаты зависят от исходных данных.

## Проверки для разработчика

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты используют временную копию базы, рабочие данные и пароль не меняют.
Подробные изменения и результат проверки: `CHANGE_REPORT.md`.
